# git: Local version history (VIP)

vip stands for very important problem.
nowadays we cannot undo changes. and this is pretty bad for us. so i propose that we have some kind of easy way for using git in ouy app. here is the context:

(btw, we could have a page only for organizing this stuff)

Local version history for projects

Context

Projects live in ~/LawEditor/<project>, or in any folder the person opens ("Open a folder…", laweditor here). LawEditor never makes these folders git repositories.

The chat and the law agent change files inside the project folder. Without version history, nothing they change can be undone, and the person isn't told. A file rewritten by the agent in one turn is gone for good in the next.

Part 1: tell the person, and offer local history

When a project has no version history, LawEditor says so once per project and offers "Turn on local history", following the existing offer pattern (harness/OFFER.bend: ask once, remember the answer).

- Local history means a git repository on this computer only. Nothing is published, and it doesn't protect against losing the disk. The offer must say this plainly. A backup to a private remote (e.g. GitHub) is a different thing and out of scope here.
- Turning it on runs git init in the project folder and writes a .gitignore with .laweditor/.

Cases the offer has to handle:

- New project in ~/LawEditor, git installed: offers "Turn on local history".
- git not installed: no button. Says history needs git and how to install it.
- Folder is already inside another git repository: doesn't offer git init, since it would create a repository inside a repository. Says the folder is already versioned by the repository at <path>, so changes go into that repository's history.
- Existing folder the person opened, not in git, with files: offers, and warns that a .git folder will be created in their folder.
- Folder already is a git repository: nothing to offer. History is on.


Part 2: the harness handles the history

With local history on, the person never needs to know git:

- At the end of each turn that changed files, the harness commits those files as LawEditor's own author (git -c user.name=LawEditor -c user.email=…), so it works even when git has no user configured. The message names the conversation and the turn.
- The turn's "files changed" line gets Undo this turn, which brings those files back to how they were before the turn.
- In a folder versioned by a parent repository (the "already inside another git repository" case above), the harness doesn't commit on its own; it only shows what changed. Commits there belong to the person.

Acceptance

- A project with no history says so once, with the right message for each case in the table.
- "Turn on local history" never creates a repository inside another one, and never shows when git is missing.
- With history on, every turn that changed files is one commit, and Undo this turn restores the files.
- The decisions (when to offer, which case applies, when to commit) live in .bend files with laws, as the rest of the harness does.

Out of scope

Backing up to a remote (GitHub or another), and branches.
